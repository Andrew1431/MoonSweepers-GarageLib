# Power UX Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A modded fuel generator shows its own look-at panel, feeds vanilla machines within its range (with the energy
taken from its battery), draws power arcs to what it feeds, and a modded cargo's canisters can be tinted.

**Architecture:** Four small library additions on `power-ux` (off `structurelib-lib`): a `ShowPanel` prefix fed by pure
`PanelText` rules; vanilla members added to the existing `SolvePower` postfix through a pure `FuelTopUp` rule; a
library-owned `MoonPowerLinks` driven from `CoreDriver.Update`; a `ShowCargo` postfix for the tint. Each goal gets a
DEVBUILD self-test check; the pure rules get xunit tests.

**Tech Stack:** C# / .NET 8, BepInEx 6 IL2CPP, HarmonyX, Il2CppInterop, xunit; Moon Sweepers on slot-2.

**Spec:** `docs/superpowers/specs/2026-11-02-power-ux-design.md`. Mechanisms: `research/POWER_UX_RECON.md`.

**Interfaces:**
- Produces:
  ```csharp
  namespace StructureLib.Pure;
  public enum PanelColour { Cyan, Amber, Coral, Mint, Muted, Dust, Sand, Stone, Tint }
  public readonly record struct PanelRow(string Label, float Fill, string Value, PanelColour Colour);
  public readonly record struct PanelLayout(string Kicker, string Title, string State, PanelColour StateColour, IReadOnlyList<PanelRow> Rows);
  public readonly record struct PanelSlot(string ShortName, double Kilograms, double Capacity, byte Cargo, bool IsInput);  // Batch slots are not passed
  public static class PanelText
  {
      public static PanelLayout Generator(string name, float rangeM, float peakKw, float suppliedKw, float batteryKwh, double chargeKwh,
          string fuelName, string fuelShortName, double fuelKg, double fuelCapacityKg, bool running, int machinesFed);
      public static PanelLayout Machine(string name, string status, bool running, int grid, float power, float usedKw, float runningKw,
          float progress, int cycles, IReadOnlyList<PanelSlot> slots, bool withPower, int maxRows);
      public static string Kw(float kw);     // "0.0", "10.0" (F1)
      public static string Kg(double kg);    // "0", "4.5" (0.#)
  }
  ```
- Rules (from the spec, Design A): Generator: kicker `FUEL POWER  ·  {rangeM:G} M RANGE`; state `Burning {fuelShortName}`
  Mint when running; else charge ≥ battery → `Battery full: burns when power is drawn` Muted; else fuelKg ≤ 0 →
  `No fuel: feed {fuelName} by belt` Coral; else `Starting` Muted. Rows: `OUTPUT` `{Kw(supplied)} / {peakKw:G} kW` fill
  supplied/peak Cyan; `BATTERY` `{chargeKwh:F1} / {batteryKwh:G} kWh` fill charge/battery Mint; `FUEL`
  `{Kg(fuelKg)} / {fuelCapacityKg:G} kg` fill kg/cap Tint; `POWERING` `1 machine` / `{n} machines` / `no machine
  running` (n = 0), fill n > 0 ? 1 : 0, Cyan when n > 0 else Amber. Fills clamped to 0..1 (a value over capacity
  shows fill 1).
  Machine: kicker `PRODUCTION  ·  {IN} INTO {OUT}` (first input slot's and first output slot's ShortName upper-cased;
  `PRODUCTION` when either is missing); state = status, or `Idle` when null/empty; StateColour Coral when grid == 0,
  else Cyan when running, else Amber. Rows: when withPower: grid == 0 → `POWER` `no power source in reach` fill 0
  Coral; else `POWER` `{power*100:F0}% · {Kw(usedKw)} of {runningKw:G} kW` fill power Cyan. Then one row per slot in
  order: label ShortName upper-cased, `{Kg(kg)} / {cap:G} kg`, fill kg/cap, colour Dust (cargo 0) / Sand (1) / Stone (2)
  / Tint (≥ 3). Then `CYCLE`: running → `{progress*100:F0}% · {cycles} done` fill progress Cyan; else `{cycles} done`
  fill 0 Muted. If the row count exceeds maxRows, drop slot rows from the end until it fits (CYCLE and POWER stay).
